# ChatMusic 领域规格说明矩阵 (Domain Specifications)

本文档矩阵是 ChatMusic 的**单一事实来源 (Single Source of Truth, SSOT)**。所有的新功能开发、缺陷修复、架构重构，必须首先与这里的核心概念对齐。

## 设计哲学与 AI 协作规范

此目录的设计初衷是：**按照业务领域概念，而非代码物理路径进行知识隔离**。
在按 Token 计费的 AI 辅助开发模式下，精准的上下文注入是最高优先级的工程实践。

* **对人类开发者**：这里是系统骨架的说明书，定义了“什么是什么”，不纠结于具体的变量名，而是锁死契约和边界。
* **对 AI 代理**：当执行任务时，仅按需加载相关的 Spec 文件，避免无关领域的噪声污染上下文。

## AI 入口流程

1. 先用本页判断任务属于哪个领域。
2. 只读取对应的领域 Spec。
3. 从该 Spec 末尾的 `代码与测试映射 (Code & Verification Map)` 进入源码和测试。
4. 优先做局部验证；不要为了理解一个小改动先扫描整个 `src/`。
5. 如果源码、测试或边界发生变化，同步更新对应 Spec。

## 路径映射纪律

每篇领域 Spec 末尾维护 `代码与测试映射 (Code & Verification Map)`，作为从概念进入代码的最小上下文索引。

* 映射路径必须指向当前仓库真实存在的文件或目录。
* 如果一个概念没有稳定的一对一测试文件，只能映射到真实源码目录或实现文件，不能写占位路径。
* 当源码迁移、测试拆分或目录重组时，同一次变更必须同步更新对应 Spec 的映射。

## 领域知识目录

为保证纯粹性，业务逻辑被拆分为以下独立概念块：

1. **[探测与捕获 (Detection)](./detection.md)**
   * 关注点：DOM 侦听、降噪、特征匹配、跨聊天平台 (Gemini/DeepSeek 等) 兼容。
2. **[播放引擎 (Playback)](./playback.md)**
   * 关注点：ABC 到音符的转换、Soundfont 调度、节拍 (BPM) 演算、跨组件生命周期同步 (高亮游标)。
3. **[乐谱渲染 (Rendering)](./rendering.md)**
   * 关注点：SVG 矢量制谱、排版响应式调整、代码级错误与质量诊断 (Diagnostics)。
4. **[播放器组件视图 (Interface)](./interface.md)**
   * 关注点：敌意环境下的 Shadow DOM 绝对样式隔离、播放控制面板状态机、无状态视图行为。
5. **[独立工作台 (Studio)](./studio.md)**
   * 关注点：Web 草稿本的持久化 (Hash URL)、分栏布局、文件导入/导出生态。
6. **[平台底座 (Platform)](./platform.md)**
   * 关注点：浏览器扩展特权 API 生命周期、Popup 配置双向状态同步、双端 (Web/Ext) 构建管线。
