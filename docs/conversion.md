# Format Conversion

ChatMusic is an ABC-first editor, renderer, validator, and playback tool. It does not ship an internal MusicXML/MXL converter.

## Current Capabilities

- **ABC to MIDI**: rendered scores can be downloaded as `.mid` files from the score toolbar. This uses abcjs' built-in MIDI generator and does not introduce a separate MIDI implementation.
- **ABC source files**: Studio can open `.abc` and `.txt` files, and can save the current source as a `.abc` file.
- **ABC rendering workflow**: Studio can validate, render, wrap, play, and export ABC sources that were written by hand, generated by AI, or produced by an external converter.

## External MusicXML/ABC Conversion

MusicXML is a large engraving format with many semantics that are easy to misrepresent in a partial converter. ChatMusic therefore points users to mature external tools instead of maintaining a built-in MusicXML/MXL importer.

Recommended tools:

- [xml2abc-js](https://wim.vree.org/js/xml2abc-js_index.html) for browser-based MusicXML to ABC conversion.
- [xml2abc](https://wim.vree.org/svgParse/xml2abc.html) for the Python command-line MusicXML to ABC converter.
- [abc2xml](https://wim.vree.org/svgParse/abc2xml.html) for ABC to MusicXML conversion.

The intended workflow is:

1. Convert MusicXML/MXL to ABC with an external converter.
2. Paste or open the resulting ABC in ChatMusic Studio.
3. Use ChatMusic for ABC diagnostics, rendering, system wrapping, playback, SVG export, and MIDI export.

## Why Conversion Is External

The project previously experimented with a small browser-local MusicXML subset converter. Real scores exposed enough edge cases that a partial converter was more likely to produce misleading notation than a dependable user workflow.

The main reasons for keeping conversion external are:

- Mature converters handle far more MusicXML semantics, including voices, staves, tuplets, lyrics, articulations, dynamics, repeats, layout, and instrument-specific notation.
- Bundling common `xml2abc` implementations into a Chrome extension requires LGPL compliance planning that this MIT-licensed project does not currently need.
- ChatMusic's strongest boundary is ABC: validation, rendering, playback, export, and AI feedback loops.

## Repository Hygiene

Local downloads of `abc2xml.py` and `xml2abc.js` are ignored by `.gitignore`. They may be useful as local reference tools, but they are not part of the source tree, are not bundled into `dist/` or `dist-web/`, and should not be copied into project-owned TypeScript code.

If the project later adopts an LGPL converter, document the compliance model first. Prefer a narrow adapter and a separately replaceable asset or worker over bundling third-party converter code into Vite chunks.

## Testing Expectations

Conversion-specific tests are no longer part of ChatMusic. Format-adjacent changes should instead verify:

- ABC source file open/save behavior in [src/shared/abc-file.test.ts](../src/shared/abc-file.test.ts).
- ABC parser diagnostics in [src/shared/abc-quality/validate.test.ts](../src/shared/abc-quality/validate.test.ts).
- Rendering, wrapping, playback, and export behavior in content and Studio tests.

Run `npm run check` after workflow or documentation changes that affect user-facing conversion guidance.
